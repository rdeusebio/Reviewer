Module 1

Foundations of GIS

What a GIS actually is, why location changes the kinds of questions you can ask, and how GIS connects to the rest of Information Technology.

1.1What is a Geographic Information System?

A Geographic Information System (GIS) is a computer-based system for collecting, storing, managing, analyzing, and displaying geographically referenced information. Chang's definition is the one to remember: GIS integrates geographic data with computer technology to support spatial analysis and decision-making.

Every piece of geographic information is made of two elements. Location information answers "Where is it?" — the position of a feature on Earth's surface. Attribute information answers "What is it?" — the descriptive details about that feature. A hospital, for example, has location information (its coordinates, 14.5995° N, 120.9842° E) and attribute information (its name, City Hospital, and its capacity, 300 beds) — you need both to fully describe it in a GIS.

Key terms to identify

Geographic Information System (GIS)
A computer-based system that collects, stores, manages, analyzes, and displays geographically referenced information (Chang).
Location information
Answers "Where is it?" — the position of a feature on Earth's surface.
Attribute information
Answers "What is it?" — descriptive details about a feature.
1.2Why Location Matters

Location changes what decisions are possible. In disaster management, location data identifies which communities are vulnerable to flooding by combining hazard maps, population data, and elevation data. In business planning, companies use GIS to pick the best location for a new branch by examining customer locations, competitor locations, and transportation networks. In transportation, GIS finds the best route between locations by analyzing road networks and traffic information.

All of this rests on spatial thinking — understanding the relationships between locations. Module 2 unpacks this in full, but the four building blocks introduced here are distance, direction, pattern, and relationships.

Key terms to identify

Distance
How far one place is from another.
Direction
Where one feature is located relative to another.
Pattern
Whether features are clustered together or evenly distributed.
Relationships
How different locations are connected to one another.
1.3GIS as an Information System

A GIS follows the same logic as any information system: it collects, stores, processes, analyzes, and presents information to support decisions. What makes it a geographic information system is that it's built from five components (Figure 1): hardware, software, data, people, and methods and procedures.

Of the five, data is considered the most important, because it's the foundation everything else operates on. GIS data splits into spatial data (the location of features — roads, buildings, rivers) and attribute data (descriptive information about those features — names, classifications, measurements). In the components diagram, software sits at the center, wired directly to hardware, data, people (above), and procedures (below) — it's the hub that ties the other four together.

The five components of GIS

Hardware
Physical equipment used to run GIS — computers, servers, GPS devices, mobile devices.
Software
Applications that process and analyze geographic data — desktop GIS, web GIS apps, database management systems.
Data
The most important component — the foundation for all GIS operations. Split into spatial data and attribute data.
People
Those who use, manage, and maintain GIS — GIS analysts, database administrators, decision-makers.
Methods and procedures
The rules, standards, and processes for running GIS effectively — data collection procedures, analysis workflows, updating processes.
1.4GIS Compared with Traditional Information Systems

A traditional information system stores and manages general information using tables and records — it's built to answer "What?" A GIS combines that same attribute data with location information, so it can answer both "What?" and "Where?" That second capability is what unlocks spatial analysis.

The classic contrast: ask a traditional database "List all hospitals," and it returns a table of names and records. Ask a GIS "Where are hospitals located within 5 kilometers of flood-prone areas?" and it returns a map plus analysis results — letting you actually see hospital locations against flood hazards, not just read about them.

Module 2

Spatial Thinking & Geographic Data

The mental toolkit behind every GIS question, how GIS organizes information into spatial and attribute data, and the workflow for solving a geographic problem.

2.1Understanding Spatial Thinking

Spatial thinking is the ability to understand the location, arrangement, relationships, and patterns of objects and events in space. It's something people already do daily without noticing — choosing the shortest route to school, finding the nearest restaurant, comparing store locations, identifying flood-affected areas. GIS just formalizes this by using computers to store, analyze, and visualize spatial information.

Here's why it matters for GIS specifically: a traditional database can tell you Hospital A has 200 beds and Hospital B has 150 — purely descriptive. A GIS can also answer spatial questions: which hospital is closer to a community, which is fastest to reach, which areas have limited healthcare access, and how many people live within a given distance of each hospital.

The four components of spatial thinking

Location
Absolute location — a precise position, usually latitude/longitude or GPS coordinates (e.g. 15.4905° N, 120.9682° E). Relative location — a place described relative to other features (e.g. a school beside a highway, a house 500m from a river).
Distance
How far apart locations are — straight-line distance, travel distance along roads, or travel time (e.g. households within a 10-minute travel distance of a health center).
Direction
The position of one feature relative to another (N, S, E, W) — used in navigation, emergency response, and transportation planning.
Pattern
How features are arranged across an area — clustered (concentrated, e.g. malls in urban centers), dispersed (spread out, e.g. farms across rural areas), or random (no predictable arrangement, e.g. some natural phenomena).

IT connection

Spatial thinking is what powers ride-sharing apps (matching riders and drivers using location, distance, traffic, routes), e-commerce delivery systems (customer and warehouse locations, delivery routes, arrival times), and smart city systems (sensors, databases, communication networks, and GIS platforms managing urban services together).

2.2Geographic Information and Spatial Data

Geographic information is any information tied to a specific location — school locations, road networks, population distribution, rainfall measurements, land-use areas. Because every geographic feature has both a position and characteristics, GIS splits that information into two categories: spatial data, which answers "Where is it?" (stored as points, lines, polygons, or raster cells), and attribute data, which answers "What is it?" (names, classifications, measurements).

The school's location identifies where it is; its attribute data describes the school itself. GIS represents real-world features using three geometry types:

Geographic feature types

Point features
A single, specific location — buildings, schools, hospitals, cellphone towers.
Line features
Length but relatively little width — roads, rivers, pipelines.
Polygon features
Areas or regions with defined boundaries — provinces, cities, lakes, land parcels.

GIS also analyzes how features relate to each other — this is called a spatial relationship:

Spatial relationships

Proximity
How close features are to one another (e.g. restaurants within 1 km of a university).
Connectivity
How features are linked together, such as roads forming a transportation network.
Containment
Whether one feature is located inside another (e.g. a city or municipality inside a province).
Adjacency
Features that share common boundaries, such as neighboring municipalities.

Two more concepts decide how well any of this represents the real world:

Scale & resolution

Scale
The relationship between distance on a map and the real-world distance it represents. A city map shows streets and individual neighborhoods; a national map shows provinces and regions, not individual buildings.
Resolution
The level of detail in geographic data. High-resolution satellite imagery shows individual buildings and roads; lower-resolution imagery shows only broad land areas or patterns.
Why it matters
Using data too general or too detailed for the task leads to wrong conclusions — a city planner needs high-resolution, large-scale data; a national planner studying population trends can use smaller-scale, lower-resolution data.
2.3Spatial Thinking in GIS Problem Solving

GIS analysis always starts with a question that needs both locations and the relationships between them. "Where should a new hospital be built?" needs population locations, existing hospitals, road accessibility, and available land. "Which communities are vulnerable to flooding?" needs elevation, rainfall, rivers, and settlement locations. "Where's the best location for a new branch?" needs customer locations, competitor locations, transportation access, and demographics.

The spatial thinking workflow (in order)

  1. Identify the problem — clearly define the question that needs answering.
  2. Identify the required data — e.g. population information, hospital locations, transportation networks.
  3. Analyze spatial relationships — examine distance, overlap, accessibility.
  4. Interpret and present results — maps, reports, and practical recommendations.

Module 2 in one paragraph

Spatial thinking runs on location (absolute vs. relative), distance, direction, and pattern (clustered, dispersed, random). GIS organizes information into spatial data ("where") and attribute data ("what"), models the real world as points, lines, and polygons, and analyzes proximity, connectivity, containment, and adjacency between them — all calibrated by the right scale and resolution. Solving a GIS problem follows a fixed workflow: identify the problem, identify the data, analyze relationships, then interpret and present.

Module 3

The Vector Data Model

How GIS stores discrete features as coordinates — points, lines, and polygons — plus attribute tables, spatial queries, topology, and how vector data gets created and edited.

3.1Understanding the Vector Data Model

A data model is a method used to represent and organize information within a computer system. In GIS, it defines how geographic features are represented, stored, and managed digitally. GIS uses two data models — vector and raster (raster is Module 4). The vector model represents features using coordinates: a series of geographic positions called vertices, where each vertex is a point with a specific coordinate location. A road, for instance, isn't stored as a picture — it's stored as coordinates like (120.950, 15.480), (120.955, 15.485), (120.960, 15.490), which GIS connects into a line.

Why use vector data

High positional accuracy
Exact geographic locations via precise coordinates (e.g. a land parcel boundary).
Efficient data storage
Stores only the coordinates needed to define a feature — far less space than image-based data.
Network analysis
The preferred format for roads, transportation, and utility networks, where connectivity and routing matter.
Easy attribute management
Every feature links to descriptive info — a school's name, enrollment, and type, for example.

Every vector feature has two components: geometry (its location and shape — point, line, or polygon) and attributes (descriptive information). Together they let GIS answer both "Where is it?" and "What is it?"

3.2Types of Vector Data

Vector data models the real world using three geometry types, each suited to a different kind of object.

The three vector geometry types

Point feature
A single, specific location, defined by an X-coordinate (longitude/easting) and Y-coordinate (latitude/northing). Used when exact location matters more than size or shape — schools, hospitals, stores, cellphone towers, GPS locations.
Line feature
Length but relatively little width, built by connecting a starting point, intermediate vertices, and a final point — roads, rivers, pipelines, transmission lines.
Polygon feature
An enclosed area with both a boundary and an interior — provinces, municipalities, lakes, land parcels.

GIS supports two kinds of queries. An attribute query searches descriptive information — e.g. SELECT hospitals WHERE beds > 100; A spatial query goes further and considers location and relationships too:

Spatial query types

Within
Finds features located inside a boundary — e.g. all schools inside a municipality.
Intersect
Finds features that cross another feature — e.g. roads that cross flood-prone areas.
Near
Finds features within a specified distance of another — e.g. facilities near a highway.
3.4Topology in Vector Data

Topology is the set of spatial relationships that define how geographic features connect to one another, and GIS enforces it so those relationships stay correct through storage, editing, and analysis.

Key topological relationships

Adjacency
Features that share common boundaries.
Connectivity
How linear features like roads or pipelines are linked together.
Containment
Whether one feature is located within another.

Without topological rules, spatial data can end up with gaps between neighboring land parcels, overlapping administrative boundaries, or disconnected road segments — all of which produce incorrect measurements, bad routing, or misleading analysis. So two rules get enforced constantly: polygon features (like administrative boundaries) must share borders without overlapping, so every location belongs to exactly one unit; line features (like roads) must connect properly at intersections and endpoints, or network analysis will wrongly conclude that travel between two points is impossible.

IT connection

Topology is the GIS version of database validation rules. Just as relational databases enforce constraints to prevent duplicate or invalid records, GIS uses topology to keep spatial relationships valid and geographic structures consistent.

3.5Vector Data Creation and Editing

How vector data gets created

Digitizing
Converting paper maps, aerial photos, or satellite images into digital vector features — e.g. tracing roads visible in satellite imagery.
GPS data collection
Field workers gather coordinates with GPS receivers, smartphones, or surveying equipment — commonly used to map roads, buildings, and utilities directly from the field.
Existing data sources
Government datasets, open-data initiatives like OpenStreetMap, and other geographic databases.

Once created, vector data usually needs editing to stay accurate: creating new features, moving existing ones to their correct locations, deleting obsolete or incorrect features, modifying attribute information, and correcting geometric errors.

Module 3 in one paragraph

Vector data represents discrete features as coordinates (vertices) organized into points, lines, and polygons, each pairing geometry with attributes — much like a database record pairs a primary key with fields. Attribute queries search the descriptive data; spatial queries (Within, Intersect, Near) search location and relationships. Topology (adjacency, connectivity, containment) keeps those relationships valid, and vector data itself comes from digitizing, GPS collection, or existing datasets.

Module 4

The Raster Data Model

How GIS represents continuous surfaces as a grid of cells, what resolution trades off, where raster data comes from, how it compares with vector, and the core raster analysis techniques.

4.1Understanding the Raster Data Model

Raster data represents geographic information as a grid of cells arranged in rows and columns. It's similar to a digital image made of pixels — but unlike an ordinary pixel, which only holds color, a raster cell holds geographic information with real-world meaning: elevation, temperature, rainfall, or land cover.

A raster dataset has four basic components: rows, columns, cells (pixels), and cell values.

Continuous vs. discrete phenomena

Continuous data
Changes gradually across space with no clear boundaries — elevation, temperature, rainfall, pollution concentration. Each cell holds a unique numerical measurement.
Discrete data
Distinct categories or classes — land use, vegetation type, soil classification. Each cell holds a code for a category (e.g. 1 = Forest, 2 = Agriculture, 3 = Urban Area — Table 15).

Common raster datasets: satellite imagery (cells record reflected energy detected by sensors — environmental monitoring, precision agriculture, disaster assessment), Digital Elevation Models / DEMs (each cell stores terrain elevation — slope analysis, watershed delineation, flood modeling), and temperature maps (each cell holds a temperature reading — climate analysis, weather forecasting).

4.2Raster Resolution and Cell Size

Resolution is the level of detail in raster data, and it's set by cell size. Smaller cells capture more detail (higher resolution); larger cells cover more ground per cell but show less detail (lower resolution).

Low-resolution images only show large-scale features like forests, cities, coastlines, and regional land-cover patterns — but that's often enough for environmental monitoring and climate studies focused on broad trends.

4.3Raster Data Sources

Where raster data comes from

Satellite imagery
Earth-observing satellites (Landsat, Sentinel, commercial platforms) — wide coverage, regularly updated. Used for land cover mapping, agricultural monitoring, environmental assessment, disaster response.
Aerial photography
Images from aircraft or drones/UAVs, usually higher resolution than satellite imagery. Used for urban mapping, construction monitoring, land surveys, infrastructure inspection, cadastral mapping.
Digital Elevation Models (DEM)
Each cell stores a numerical elevation value. Used for slope calculation, watershed delineation, flood modeling, terrain visualization.
Scanned maps
Paper maps digitized by scanning; need georeferencing to align with real-world coordinates. Used for preserving historical maps and comparing historical vs. current landscapes.
Sensor data
Weather stations, environmental sensors, IoT devices measuring temperature, humidity, air quality, soil moisture. Supports real-time monitoring for meteorology, agriculture, public health, disaster risk reduction.

4.5Raster Analysis Concepts

Core raster analysis techniques

Reclassification
Converts raster values into new categories based on set criteria — e.g. elevation grouped as 0–100m = Low, 101–500m = Medium, above 500m = High (Table 22). Used for suitability analysis, hazard assessment, thematic mapping.
Map algebra
Performs mathematical/logical operations across one or more raster layers, cell by cell — e.g. combining rainfall, elevation, and soil layers to flag flood-susceptible areas.
Surface analysis
Examines a continuous surface, usually a DEM, through slope (how steep the terrain is), aspect (the compass direction a slope faces), and elevation (height above sea level).
Raster overlay
Combines multiple layers to score suitability — e.g. soil type + rainfall + slope to identify the best agricultural land.

Raster data stores geographic information as a grid of cells, each with a location and a value — good for continuous phenomena (elevation, rainfall, temperature) where vector's sharp boundaries don't fit. Resolution is set by cell size and trades detail against file size and processing speed. Raster comes from satellites, aerial/drone photography, DEMs, scanned maps, and sensors, and is analyzed through reclassification, map algebra, surface analysis, and raster overlay — techniques that connect straight into computer vision, AI, and big data processing.

Description practice

Explain each one out loud before opening the hint. The hint is a checklist, not a script — put it in your own words.

Why can a GIS answer more questions than a traditional database? Use the hospital example.
  • Traditional IS: tables and records, answers "What?" only
  • GIS: attribute data + location, answers "What?" and "Where?"
  • Example: "List all hospitals" (table) vs. "hospitals within 5km of flood-prone areas" (map + analysis)
Describe the five components of a GIS and how they work together.
  • Hardware, software, data, people, methods & procedures
  • Data is the foundation — most important component
  • Software is the hub connecting hardware, data, people, procedures
Explain the difference between spatial data and attribute data, with an example.
  • Spatial = "where" (points/lines/polygons/raster cells)
  • Attribute = "what" (names, classifications, measurements)
  • Example: Central Elementary School — location vs. Type: Public, Students: 850
Discuss the four components of spatial thinking, with one example each.
  • Location (absolute vs. relative)
  • Distance (straight-line, travel distance, travel time)
  • Direction (N/S/E/W — navigation, emergency response)
  • Pattern (clustered, dispersed, random)
Explain proximity, connectivity, containment, and adjacency, with an example each.
  • Proximity — restaurants within 1km of a university
  • Connectivity — roads forming a network
  • Containment — a municipality inside a province
  • Adjacency — neighboring municipalities sharing a border
Describe the vector data model and explain why it suits roads or land parcels.
  • Coordinates / vertices define geometry
  • High positional accuracy, efficient storage
  • Good for network analysis (routing, connectivity)
  • Easy attribute management (geometry + attributes)
Explain the difference between an attribute query and a spatial query.
  • Attribute query — descriptive data only (SELECT hospitals WHERE beds > 100)
  • Spatial query — considers location/relationships too
  • Name the three types: Within, Intersect, Near, with an example each
What is topology, and why does GIS need it? Give an example of what breaks without it.
  • Definition: relationships that keep features correctly connected
  • Adjacency, connectivity, containment
  • Without it: gaps between parcels, overlapping boundaries, disconnected roads → bad routing/analysis
Describe the raster data model and how it differs from vector.
  • Grid of cells (rows/columns), each cell = location + value
  • Vector = discrete features with boundaries; raster = continuous surfaces
  • Compare data structure, accuracy, typical file size, and analysis type
Explain the trade-off between high-resolution and low-resolution raster data.
  • Cell size drives resolution — smaller cells = more detail
  • High-res: excellent detail, large file size, slower processing, urban/engineering use
  • Low-res: less detail, small file size, faster processing, regional/climate use
Walk through the four-step spatial thinking workflow using a healthcare-access example.
  • 1. Identify the problem — e.g. areas lacking healthcare facilities
  • 2. Identify required data — population, hospital locations, transport networks
  • 3. Analyze spatial relationships — distance, overlap, accessibility
  • 4. Interpret and present — maps, reports, recommendations
Using the flood mapping example, explain how vector and raster data work together.
  • Vector: houses, roads, administrative boundaries
  • Raster: elevation, rainfall, flood depth
  • Combined, they support a more complete flood assessment for planning and disaster management
